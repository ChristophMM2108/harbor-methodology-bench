Experiment runbook: SDD Agent Kit vs clean baseline

The data-science and machine-learning benchmark categories, minus one excluded outlier — 10 tasks, 2 conditions, 20 trials. Every command below was executed against this repository except the two that build images or spend model tokens (preflight and the run itself), which are marked as such.

1. What this experiment is

Conditions
baseline (benchmark task and nothing else, always generated) and sdd (the frozen SDD Agent Kit snapshot already in toolkits/sdd/, SHA dc4b09e730f6e38a43ba85b44991bb6de890b6d9). dfg is deliberately excluded.
Tasks
10 — the 11 tasks whose [metadata].category is data-science (8) or machine-learning (3), minus caffe-cifar-10 (§7).
Task set file
config/tasks-ds-ml.txt — the exclusion lives in one place, and every command reads it.
Agent
claude-code with claude-sonnet-5.
Matrix
2 cells × 10 tasks × 1 attempt = 20 trials.
Job prefix
ds-ml → jobs land in jobs/ds-ml-claude-{baseline,sdd}-<task>/.
Two decisions taken for you, change them if you disagree.
  • Codex is left out. All 15 Codex trials in the last matrix run failed with ApiUsageLimitError before reaching the task (see TODO.md). Including it would add 20 trials that fail at startup. The config carries the two Codex cells commented out — uncomment them once the quota is renewed and re-run the same commands.
  • One attempt per cell. Enough to see whether the pipeline and the conditions hold on these tasks, but not enough to claim a methodology effect: with 10 tasks and one attempt, a single flaky trial moves the success rate by 10 points. Add --attempts 3 when you want a reportable mean — it triples cost and wall-clock.

2. Prerequisites

All 10 tasks are CPU-only (gpus = 0) and ship prebuilt images, so no GPU or Dockerfile-build setup is needed. Each declares 10 GB of storage and up to 8 GB of memory.

Two things a fresh clone does not have, because both are git-ignored:

  • The task suite — source-tasks/terminal-bench/ must hold the 89 Terminal-Bench 2.0 tasks. Fetch procedure: README §3. Check with find source-tasks/terminal-bench -mindepth 2 -maxdepth 2 -name task.toml | wc -l.
  • Credentials — config/local.env with CLAUDE_FORCE_OAUTH=1 and CLAUDE_CODE_OAUTH_TOKEN="…" from claude setup-token. The runner refuses to start without this file.

3. Setup: the two configuration files

The experiment configuration

The shipped config/experiments.yaml declares six cells over two toolkits, so this experiment has its own file — config/experiments.sdd-ds-ml.yaml:

# machine-learning task categories.

source_root: source-tasks/terminal-bench
generated_root: generated
repetitions: 1

models:
  claude-code: claude-sonnet-5
  # codex: gpt-5.6-terra

snapshot_excludes: [".git", ".venv", "venv", "node_modules", "__pycache__",
                    ".ruff_cache", ".pytest_cache", ".mypy_cache", ".tox", ".DS_Store"]

skill_sources: [".claude/skills", ".agents/skills", "skills"]

toolkits:
  - id: sdd
    snapshot: toolkits/sdd/snapshot

matrix:
  - {id: claude-baseline, agent: claude-code, toolkit: baseline}
  - {id: claude-sdd, agent: claude-code, toolkit: sdd}
  # - {id: codex-baseline, agent: codex, toolkit: baseline}
  # - {id: codex-sdd, agent: codex, toolkit: sdd}
The file must live in config/. load_config() resolves relative paths from the config file's parent's parent (src/harbor_methodology_bench/config.py), so a config outside a repository subdirectory resolves source_root to the wrong place and fails with source root does not exist.

4. The commands, in order

Every command carries the same two flags: --config and --tasks-file. Nothing selects by category any more, so caffe-cifar-10 cannot re-enter the run by accident.

  1. Preview the selection ✓ run

    ./scripts/catalogue.sh --config config/experiments.sdd-ds-ml.yaml \
  --tasks-file config/tasks-ds-ml.txt --ids-only
    distribution-search
hf-model-inference
llm-inference-batching-scheduler
mcmc-sampling-stan
mteb-leaderboard
mteb-retrieve
query-optimize
reshard-c4-data
rstan-to-pystan
sam-cell-seg

    Drop --ids-only for the axis rollup of the set: spec-dense 7, modify-existing 3, greenfield-algorithmic 2, underspecified 2, verification-heavy 2, long-horizon 1, quick 1.

  2. Generate the variants ✓ run

    ./scripts/generate-variants.sh --config config/experiments.sdd-ds-ml.yaml \
  --tasks-file config/tasks-ds-ml.txt --force
    generated baseline/distribution-search  markers=- skills=0
generated sdd/distribution-search  markers=CLAUDE.md,AGENTS.md skills=7
…
generated baseline/sam-cell-seg  markers=- skills=0
generated sdd/sam-cell-seg  markers=CLAUDE.md,AGENTS.md skills=7

    20 variant directories under generated/baseline/ and generated/sdd/. Every sdd line must show both instruction markers and 7 skills; a baseline line must show neither.

  3. Validate host-side ✓ run

    ./scripts/validate-variants.sh --config config/experiments.sdd-ds-ml.yaml \
  --tasks-file config/tasks-ds-ml.txt
    validated 10 tasks across 2 variants

    This re-derives each generated environment through the code path that produced it and hash-compares, so it catches a tampered benchmark file or a hand-edited generated Dockerfile.

  4. Preflight from inside the containers — builds 20 images, not yet run

    ./scripts/preflight-variants.sh --config config/experiments.sdd-ds-ml.yaml \
  --tasks-file config/tasks-ds-ml.txt

    Expect one block per task:

    preflight distribution-search ...
  ok    baseline: workdir=/app markers=- skills=0 payload_files=0
  ok    sdd: workdir=/app markers=CLAUDE.md,AGENTS.md skills=7 payload_files=47

    This is the step that decides whether the experiment is real: it proves the baseline workdir is byte-identical to the untouched base image and that all 7 SDD skills plus the instruction files reached the agent's workdir. Budget time and disk for it — 10 base images are pulled on first run, and each variant adds one thin payload layer. A warn … archived on collision line is tolerable (the benchmark file wins by design); an error on CLAUDE.md is not, and the runner will refuse that cell.

  5. Dry-run the matrix ✓ run

    ./scripts/run-pilot-experiment.sh --config config/experiments.sdd-ds-ml.yaml \
  --tasks-file config/tasks-ds-ml.txt --job-prefix ds-ml --dry-run
    [20/20] Job: ds-ml-claude-sdd-sam-cell-seg
       Task: sam-cell-seg (sdd)
       Agent: claude-code (claude-sonnet-5)
   [DRY RUN] harbor run -p generated/sdd/sam-cell-seg -a claude-code -m claude-sonnet-5 -n 1 --env-file config/local.env --job-name ds-ml-claude-sdd-sam-cell-seg
✓ Dry run completed for 20 trial invocations.

  6. Run it — spends model tokens

    ./scripts/run-pilot-experiment.sh --config config/experiments.sdd-ds-ml.yaml \
  --tasks-file config/tasks-ds-ml.txt --job-prefix ds-ml

    The runner re-runs validate and preflight as a gate, then refuses any individual cell whose .methodology-bench-preflight.json is missing or failed. It is resumable: a job that finished is skipped, one that was interrupted is cleaned and re-run. Pass --force to re-run finished cells, --attempts 3 for repetitions, and --timeout-multiplier F to scale every task's timeouts run-wide.

  7. Report — after the run

    python3 scripts/report.py --jobs-dir jobs/ --pattern "ds-ml-*" \
  --md-out results/ds-ml_report.md \
  --json-out results/ds-ml_summary.json

    Per cell: success rate, mean reward, average duration, token consumption, cost, and the adherence columns (skills registered, skills invoked, config files named). Per task: which of the 10 passed under which condition.

    The two void caffe-cifar-10 jobs have already been moved out of the pattern. They used to be jobs/ds-ml-claude-{baseline,sdd}-caffe-cifar-10, matched ds-ml-*, and would have dragged both conditions down with a failure about the container budget rather than the methodology. They now live at jobs/void-caffe-cifar-10-{baseline,sdd}/, so the evidence in §7 stays on disk while the report ignores it. Delete them whenever you no longer need it: 
    rm -rf jobs/void-caffe-cifar-10-baseline jobs/void-caffe-cifar-10-sdd

All of it, copy-paste

C=config/experiments.sdd-ds-ml.yaml
F=config/tasks-ds-ml.txt

./scripts/catalogue.sh            --config $C --tasks-file $F --ids-only
./scripts/generate-variants.sh    --config $C --tasks-file $F --force
./scripts/validate-variants.sh    --config $C --tasks-file $F
./scripts/preflight-variants.sh   --config $C --tasks-file $F
./scripts/run-pilot-experiment.sh --config $C --tasks-file $F --job-prefix ds-ml --dry-run
./scripts/run-pilot-experiment.sh --config $C --tasks-file $F --job-prefix ds-ml
python3 scripts/report.py --jobs-dir jobs/ --pattern "ds-ml-*" \
  --md-out results/ds-ml_report.md --json-out results/ds-ml_summary.json

A variable holding a single value like $C is safe in zsh; a variable holding several words is not — zsh does not word-split unquoted parameters, so a $SET="--a x --b y" style variable arrives as one argument and the CLI rejects it. That is why the selection is a file rather than a variable.

6. Budget

Agent timeouts across the 10 tasks total 7 h 30 min, so 20 sequential trials have a worst case of about 15 hours of agent time plus verifier and image-build time. Real runs finish well short of that — the only measured Claude Code trials in this repository (five easier tasks) averaged 200–800 s and roughly $0.40–$1.30 each.

Extrapolating to this heavier set: order 6–15 hours wall-clock and $20–$55 for the 20 trials at one attempt. Treat that as an order of magnitude, not a forecast — three of these tasks are hard and sam-cell-seg alone allows two hours. Shake the pipeline out on the cheapest task first:

./scripts/run-pilot-experiment.sh --config config/experiments.sdd-ds-ml.yaml \
  --task hf-model-inference --job-prefix ds-ml-probe

7. Why caffe-cifar-10 is excluded

The first attempt at this experiment lost both caffe-cifar-10 trials, and the two exception names Harbor printed are both misleading. What actually happened, from the trial artifacts and the host kernel log:

CellHarbor saidWhat really happened
claude-baseline AgentTimeoutError after 1200 s Genuine budget exhaustion. The agent cloned BVLC Caffe 1.0, apt-installed the dependency stack, patched io.cpp for modern protobuf and OpenCV, ran make all -j2 (~3 min), downloaded CIFAR-10, and was still mid-build when the 20-minute agent budget ran out. 41 tool calls, no idle time.
claude-sdd ApiRateLimitError Not a rate limit. Exit code 137 = SIGKILL. The kernel log shows Memory cgroup out of memory: Killed process … (cc1plus) inside the container's cgroup. Harbor's _classify_exec_error maps exit 137 to ApiRateLimitError, which is simply the wrong label. The rate_limit_event in the agent log reads status: allowed — the account was never throttled.

Root cause of the OOM: nproc inside the container returns 16 — the host's core count — because Docker's --cpus quota is a scheduler limit, not a visible CPU count. The agent read 16, ran make all -j$(nproc), and 16 parallel cc1plus processes exceeded the task's 2048 MB memory limit. Four cgroup OOM kills were logged across the two trials. Both conditions are equally exposed; the baseline simply happened to guess -j2.

So the task is an environment-engineering task wearing a machine-learning label: build a C++ framework from source, on 1 CPU, in 2 GB, within 20 minutes. Neither the bare agent nor the SDD-equipped agent gets near the reward, and the failure is a property of the container budget, not of the methodology — which is exactly the kind of task that adds variance without adding an answer. It is therefore out of the set, by name, in config/tasks-ds-ml.txt.

If you want it back

Run it on its own, with more wall-clock, and report it separately from the 10-task result:

./scripts/generate-variants.sh --config config/experiments.sdd-ds-ml.yaml \
  --task caffe-cifar-10 --force
./scripts/preflight-variants.sh --config config/experiments.sdd-ds-ml.yaml \
  --task caffe-cifar-10
./scripts/run-pilot-experiment.sh --config config/experiments.sdd-ds-ml.yaml \
  --task caffe-cifar-10 --job-prefix caffe --timeout-multiplier 3 --force

The runner passes --timeout-multiplier through to Harbor and applies it to every cell of the run, so the comparison inside that run stays fair. It does change the budget the benchmark declares, so report the multiplier with the numbers — and keep in mind that a methodology's value can itself be budget-dependent. A separate --job-prefix keeps the jobs out of the ds-ml-* report.

Worth knowing in general: Harbor labels several container-level failures with API-sounding exception names. Check <trial>/exception.txt for the exit code before believing the label — 137 is a kill (usually OOM), 124 is a command timeout, and a genuine quota failure shows up in the agent log's rate_limit_event with a status other than allowed.

8. Reading the result honestly

  • No control axis. Selecting by category, not by axis, gives a set that is 7/10 spec-dense — the axis SDD's sdd-specify / sdd-tasks / sdd-analyze skills target. That is a fair test of the claim, but it contains no cheap control, so it cannot show what the methodology costs where it should not help. A companion run with --suite quick --limit 3 and the same config supplies that.
  • Availability is not use. Preflight proves the 7 skills reached the container. The adherence columns show whether the agent invoked them. Zero invocations with a passing preflight is a finding about the toolkit, not a broken run — SDD gates itself to "substantial feature development", so short tasks skipping it is the kit behaving as written.
  • Claude Code loads CLAUDE.md silently. An empty Config Referenced means the agent never named the file, not that it never received it.
  • 10 tasks × 1 attempt is a pipeline check, not a result. One flaky trial is 10 points of success rate. Re-run with --attempts 3 before drawing a conclusion.
  • Say that a task was excluded. A 10-task result is not an 11-task result; config/tasks-ds-ml.txt carries the reason in its header so the exclusion travels with the set.

9. Housekeeping

  • Resuming after Ctrl-C is safe. An interrupted run leaves a job directory holding a result.json with finished_at: null and cancelled trials. The runner inspects that file instead of merely testing for its existence, so such a cell is cleaned and re-run rather than counted as done. Cells that finished — including ones that finished with an exception — are skipped; use --force to redo those.
  • generated/ also holds variant directories from earlier selections. They cannot join this run — the runner resolves its task list from --tasks-file, not from the directory — but rm -rf generated/ before step 2 gives a clean tree. The two caffe-cifar-10 variants have already been removed.
  • jobs/ is git-ignored, so the 20 job directories stay local. The tracked artifacts are the two files under results/.
  • Preflight leaves tagged images behind (harbor-methodology-bench-preflight:<condition>-<task>); clear them with docker image prune when convenient.
  • When the Codex quota is renewed: uncomment the model and the two cells in config/experiments.sdd-ds-ml.yaml, then re-run steps 4–7. Existing Claude jobs are skipped, so only the new cells execute.
