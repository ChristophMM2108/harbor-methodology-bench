# SDD Specify

1. Read `docs/sdd/constitution.md`.
2. Identify/create `docs/sdd/specs/<feature>/`.
3. Inspect relevant repository behavior and existing docs/code.
4. Write problem, goals, non-goals, actors, stories, requirements, acceptance criteria, constraints, security, compatibility, and observability.
5. Give requirements and acceptance criteria stable IDs.
6. Do not invent unresolved material behavior; record it as an open question.
7. Existing spec changes increment the revision and update the change log.
8. Keep the spec behavior-first; implementation choices belong in the plan.

Ready means scope, non-goals, testable requirements, concrete acceptance criteria, and material risks are explicit.
