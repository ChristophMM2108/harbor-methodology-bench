# SDD Clarify

1. Read the spec and constitution.
2. Inspect repository behavior only where it can answer an ambiguity.
3. Identify questions that could change behavior, scope, data, security, compatibility, or verification.
4. Ask the user targeted high-impact questions.
5. Record answers in Decisions / Clarifications.
6. Update affected requirements/criteria and increment the revision when behavior changes.
7. Do not make product decisions on the user's behalf.
8. Mark the spec `clarified` only when material ambiguity is resolved.
